# 混合型

混合型不是把多个完整模板首尾拼接，而是用一个公共核心、一条统一工作流和若干必要模块共同描述行为。

## 选择主类型

主类型负责决定整体工作逻辑：

- 有明确交付和完成标准时，通常以任务执行型为主。
- 持续处理多类领域请求时，通常以通用型为主。
- 纯沉浸互动中，人设决定主要体验时，可以角色扮演型为主。
- 检索问答本身就是主要工作时，可以知识库型为主。
- 外部工具编排本身就是主要工作时，可以技能调用型为主。

其他类型作为辅助模块嵌入。只添加会改变行为的模块。

## 合并方法

1. 先写一次角色、目标、范围、输入和输出，不在每个模块重复。
2. 建立一条端到端工作流。
3. 把知识检索放在需要事实依据的步骤，把工具调用放在需要外部能力的步骤。
4. 最后应用人设和表达风格；它不改写事实、工具结果或授权状态。
5. 合并重复限制，并显式解决互斥规则。

建议的内部优先级：

安全与授权 > 事实和知识依据 > 任务目标与完成标准 > 工具调用协议 > 人设与语气 > 默认格式。

## 常见组合

### 任务 + 工具

任务流程决定先后顺序，工具调用协议嵌入对应步骤。先检查输入，再调用；外部影响操作在执行前确认；工具失败时交付可用的部分结果。

### 知识库 + 搜索工具

明确来源分工和优先级。例如，内部制度只以知识库为准；公开、时效性信息可以搜索。回答中区分内部资料、外部来源和推断，不能用搜索结果悄悄覆盖内部规则。

### 角色 + 知识库

知识库决定事实内容，人设只决定表达。资料不足时以符合角色语气的方式说明依据不足，但不虚构角色“记得”的事实。

### 通用 + 知识库 + 工具

通用核心负责理解多样请求；知识库和工具都按条件启用。避免问候也检索、简单改写也调用外部工具。

## 冲突扫描

重点检查：

- “每轮必调工具”与“仅必要时调用”。
- “只按知识库回答”与“可用常识补全”。
- “绝不承认缺失”与“禁止编造”。
- “始终保持角色”与“用户可退出角色或要求事实说明”。
- “自动完成全流程”与“外部操作前必须确认”。
- 多个模块对输出格式、语言、篇幅或来源优先级的不同规定。

能按真实能力、授权和事实边界保守解决时，直接给出统一版本并说明调整；若会改变用户核心意图，再提出聚焦问题。

## 推荐结构

- 角色、目标与范围
- 输入与前置条件
- 统一工作流程
- 条件式工具调用
- 知识与事实依据
- 交互、人设与语言风格
- 输出契约
- 异常、授权与完成标准

删除任何不影响实际行为的章节。

## 交付检查

- 能否用一句话说清主类型和每个辅助模块的职责？
- 是否只有一条不矛盾的工作流和一套来源优先级？
- 人设、知识和工具是否各自待在正确的层级？
